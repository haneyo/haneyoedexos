## 关键经验 / 教训(本次新增)

1. **browsh 启动 URL 是「位置参数」,没有 `--startup-url` flag**。#58 之前的 browsh 入口写的是 `browsh --startup-url https://lite.duckduckgo.com/lite` — pflag 拒绝未知 flag → 浏览器启动即死。**这很可能就是历史上「浏览器不可用」的根因**,不是 browsh 本身不能用。正确写法:`browsh <URL>`(位置参数)。**建议新增 memory**
2. **firstboot 脚本「内联 heredoc vs 独立脚本」双向漂移**:权威交付物是 `install-edex.sh` 内嵌 heredoc(实际经 late-command 装进系统),`packaging/install/edex-firstboot.sh` 是参考/修复副本。改任一侧都要同步另一侧,否则(公钥、claude 预设、自动登录)装出来的系统会丢功能。**建议新增 memory**
3. **patch-appimage.sh 的 targets 数组元素必须对象,不能放空对象/空元素**:迭代 `t.path`/`t.name`/`t.expectOut` 会崩;要「跳过某旧目标」用裸数组注释占位。
4. **patch 目标是 minified 版渲染器**(release-renderer-minified):anchor 一律用字符串字面量特征串(patch-expectout-minify-trap),验证前须从待补丁 AppImage 现抽 asar,不要用陈旧抽取。
5. **fresh-skip 模式**:release 从当前源码构建,源码已含 browsh 位置参数等全部特性 → 对应 patch 目标的 anchor 不匹配 → 目标自动跳过;patch 只负责「老构建覆盖」(如老 AppImage 补 browsh 修复)。本轮以真实 NEW_OLD 内容跑了 derivation 验证:无 carbonyl、无 --startup-url、位置参数在、cover 方法保留、htop 移除、xterm CSS + ws-close 保留,全过。
6. **cli-start.html 点击可靠性**:终端浏览器点击可能偏上一行,搜索页按钮目标保持 ≥2 行高(12px 22px padding)browsh 同样受益;键盘 1-4 切换引擎是可靠路径(UI 键盘可操作要求)。
