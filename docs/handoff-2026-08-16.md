### 代码审查结论(已全部完成,2026-08-15)
**已排查排除嫌疑:**
- **plymouth 主题 edex**:edex.plymouth 语法正常(two-step 主题),throbber/animation 帧都解出确认打包进 ISO,`build-iso.sh` 342-348 行把 edex.plymouth + throbber/ + animation/ 拷进 `nocloud/`。不是主题损坏导致卡死
- **edex-firstboot.sh 两个副本一致**:install-edex.sh 556-791 行嵌入副本 vs `packaging/install/edex-firstboot.sh` 独立文件,仅注释差异
- **grub/kernel cmdline**:装好的系统用 `/etc/default/grub` 的 `quiet splash pcie_aspm=off`;U 盘引导注入的 `autoinstall ds=nocloud;... systemd.unit=multi-user.target` 只影响 U 盘安装引导,**不会进装好的系统**

**唯一硬嫌疑(未排除):#72 firstboot ordering cycle**
```ini
# /etc/systemd/system/edex-firstboot.service
[Unit]
After=cloud-init.target systemd-user-sessions.service
Before=lightdm.service
[Install]
WantedBy=cloud-init.target
```
- 这个修复(memory `systemd-firstboot-ordering-cycle`)是 v2.4.5 推的,**从未经过 fresh 真机验证**
- 若 ordering 仍有问题,两条死链都与症状吻合:
  - firstboot 不跑 → autologin 占位符 `AUTOLOGIN-USER-NOT-CONFIGURED` 没被覆盖 → lightdm crash-loop(黑屏/闪退)
  - firstboot oneshot 卡住 → multi-user.target 达不到 → plymouth 永不退出 → **永久转圈 + TTY 被 plymouth 锁住**(最贴合「转圈 + 无法进终端」)
- 可疑卡点:`HOME="/home/$U" rime_deployer --build >/dev/null 2>&1 || true` — `|| true` 只保护失败退出码,**不保护挂起**(rime 首次 build 若卡 D-Bus/网络会无限等);以及 `chown -R "$U" /opt/firefox /usr/local/lib/node_modules /usr/local/bin`(大目录递归)

### U 盘刷写注意事项(给用户)
- macOS 写 U 盘需管理员权限:osascript `do shell script "...dd..." with administrator privileges`
- macOS **普通权限读块设备会返回空**(误判「U 盘没写入」),验证要管理员权限
- hybrid ISO 验证:MBR isohybrid(`eb63 9090` + Floppy)+ PVD(`01CD001`)+ EFI(`bootx64.efi`)
- **U 盘是最大变量**——用户自己重烧是排除它的正确做法
