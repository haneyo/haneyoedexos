## 重大突破:boot 卡死根因定位(2026-08-16)
- 用户重烧 U 盘装 v2.4.9 **仍卡 plymouth logo** → 排除 U 盘刷写问题,坐实系统 boot 链路
- 用户在 GRUB 手动删 `quiet splash` 引导 → **boot 日志暴露卡点**:
  `A start job is running for systemd-networkd-wait-online.service (2min / no limit)`
- **根因**:安装器 subiquity 按安装时的网络回答 enable 了 `systemd-networkd` + `systemd-networkd-wait-online`;但 eDEX 用**纯 NetworkManager**(netplan renderer: NetworkManager)。wait-online 无接口可等 → systemd 255 起无限等待(no limit)→ 卡死 boot → plymouth 永不退出 → 永久 logo
- **v2.4.5 的 firstboot ordering cycle 修复已确认代码层正确且生效,非本次元凶**(排除了之前最大嫌疑;install-edex.sh 内嵌 service 是 `WantedBy=cloud-init.target` 修复版)
