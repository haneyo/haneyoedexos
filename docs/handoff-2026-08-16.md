### 语音输入「说话无反应」三断点修复(2026-08-16,已提交 cd80b34)
- **现象**:#94 模型就位后麦克风按钮已能点亮/置灰,但按下说话文字不回显、终端无输入(用户:「按下麦克风按钮确实有反映了,但是我说话却没有反应」)
- **根因定位**:sherpa-onnx 识别链路本身端到端验证通过(test_wavs → 中文文本),断点在 IPC 传输与回填,**三处独立 bug 叠加**:
  1. **`voice:chunk` IPC 通道类型不匹配**:渲染层 `ipcRenderer.send("voice:chunk", samples)`(fire-and-forget 流式音频,~4 次/秒),主进程 `_boot.js` 却用 `ipc.handle` 注册 → send/handle 不配对,**音频数据被静默丢弃**,识别器从未收到波形
  2. **无实时 partial 反馈**:主进程识别出文本后 `win.webContents.send("voice:partial", ...)`,渲染层从未监听 → 说话过程无文字回显,用户以为没反应
  3. **`_insert` 回填目标错误**:写入用 `t.write(text)`,但 `window.term[0]` 是自定义 Terminal 包装类(terminal.class.js `this.term = new this.xTerm(...)`),顶层没有 `.write`,xterm 实例在 `.term` 下 → 回填被静默丢弃
- **代码修复**:
  - `src/_boot.js`:`ipc.handle("voice:chunk")` → `ipc.on("voice:chunk")`(关键一行,注释注明必须 on 不能 handle)
  - `src/_renderer.js`:语音角标创建后追加 `#edex_voice_partial` 气泡 + `ipc.on("voice:partial")` 实时回显;`_insert` 改判 `t.term && typeof t.term.write === "function"` → `t.term.write(text)`;`stop()` 清空气泡
  - `src/assets/css/browser.css`:新增 `.voice_partial` 气泡样式(角标上方绝对定位,非空才显示,cyber 风格)
- **验证**:`node --check` 全过;IPC 配对断言(渲染层 send 频道 vs 主进程 on/handle 注册)60/60 全匹配
- **待办**:v2.4.12 AppImage 部署笔记本后真机验收「说话 → 气泡回显 → 回车进终端」
